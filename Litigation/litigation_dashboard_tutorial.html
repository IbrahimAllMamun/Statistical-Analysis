01What the dashboard is for

One report for the whole litigation portfolio

The dashboard reads the latest litigation snapshot from the analytics database and presents it as an interactive, self-contained web page — no login, no server. It always shows the data as of the Report Date printed in the top-right corner.

📊Summarise

See total cases, suit value, receivable, overdue and average aging across NI, ARA and ARAE at a glance.

🔎Investigate

Drill from a client, to an account, to a single case — with the full case file and hearing history.

🎛️Filter

Narrow by branch, customer, account, product, status and upcoming hearing window in real time.

⬇️Export

Download exactly what you have filtered to a CSV file for offline work or sharing.

💡

Self-contained & offline. The whole dashboard is a single HTML file. You can open it directly in a browser or email it — all the data and interactivity travel inside the file.

02Getting your bearings

Layout & navigation

  • 1Tab bar. Switch between SUMMARY, NI, ARA and ARAE. The active tab is highlighted in white.
  • 2Report Date. The "as-of" business date of the data. Everything you see reflects this date.
  • 3Filter rail. All the controls that narrow the table live here, on the left of every page.
  • 4Data area. The summary table or the case register, filling the rest of the page.
🧭

Tip: the tab bar and Report Date stay put on all four pages, so you always know where you are and how current the data is.

03The SUMMARY tab

The portfolio at a glance

The Summary opens on three rows — one for each suit type — with a bold Total line beneath. It's the fastest way to gauge exposure before you dive into individual cases.

  • ANature of Suit — NI Act, ARA and ARAE, each a group you can expand.
  • BCases — number of distinct litigation cases in that bucket.
  • CSuit Value & Receivable — the claimed value and the litigation receivable, formatted in the lakh/crore convention.
  • DOverdue — total overdue amount tied to those cases.
  • EAging (Avg.) — the average age of the cases, in days.
  • FTotal row — column totals for whatever is currently filtered in.
🔢

Totals follow your filters. Change a branch or status and the Total line recomputes instantly, so it always reflects the slice you're looking at.

04Summary · drill into statuses

Expand a suit type to see its stages

  • 1Click the ► arrow next to any suit type to expand it.
  • 2The rows underneath are the Present Case Status stages — Summon Return, Charge Hearing, Argument, For Judgment, Judgment… — each with its own case count and money totals.
  • 3Statuses are listed in procedural order (filing → evidence → judgment → disposal), not alphabetically, so the table reads like the life-cycle of a case.
  • 4Click the ▼ arrow again to collapse it back.
📌

Only the suit-type rows expand here — the status rows are the deepest level in Summary. For individual cases, use the NI / ARA / ARAE tabs.

05Summary · filters

Slice the summary

  • 1Branch — restrict every total to a single branch.
  • 2Product Category — SME is ticked by default; add Other to include the rest of the book.
  • 3Litigation Status — Active and InActive are both on by default here, so totals cover the whole portfolio.
  • 4Upcoming Hearing — keep only cases whose next hearing falls in a chosen window (see the dedicated slide).
  • 5Clear all — resets every filter back to its default in one click.
06The case registers

Three tabs, one identical layout

NI, ARA and ARAE each list the individual cases for one type of suit. They look and behave exactly the same — learn one and you know all three.

NINegotiable Instrument Act

Cheque-dishonour cases under the NI Act. Typically the largest register, driven by the cheque tied to each account.

ARAArtha Rin Aine

Money-loan-court suits filed to recover the outstanding under the Artha Rin Adalat Ain.

ARAEARA Execution

Execution cases that enforce a decree already obtained in an Artha Rin suit.

🔁

Because the three tabs are structurally identical, every instruction on the next slides applies equally to NI, ARA and ARAE.

07Reading the case table

Grouped by client, then account, then case

  • 1Name / CIF — the client name with their CIF number in a green badge, e.g. 434732.
  • 2Account Number — collapsed to a count ("1 Account", "3 Accounts") until you expand.
  • 3Case ID — likewise shown as "4 Cases" at the group level.
  • 4Branch and Litigation Status — the owning branch and a count of active cases.
  • 5Pagination — the row count, page-size selector and page jumper sit at the bottom.

09The case file

Everything about one case

  • 1Case Info — nature of suit, suit value, filing date, law firm, court no, next hearing, cheque number and litigation receivable.
  • 2Present Case Status — the current stage, highlighted in amber.
  • 3Active Status — green when the case is Active, red when InActive.
  • 4Account Info — RM name, product, URPA, overdue, principal/interest OD, MOD, LPI and excise duty.
  • 5Case History — every past hearing: the date, the status pill, and the days between hearings.
10Reading the colours

What the pills mean

Colour is used consistently across the whole dashboard, so a glance tells you a case's health and where it stands.

Case & hearing status

Statuses in the case file and history are tinted by type:

Summon Return Paper Submission Steps Warrant of Arrest Withdrawn / Transferred
Active InActive

Aging (days between hearings)

In the Case History, the Duration pill shows how long a case sat at each stage:

under 30 dayshealthy — moving quickly
30 – 90 dayswatch — some delay
90+ daysslow — long gap between hearings
🎨

The same green / amber / red logic recurs everywhere: green is good and current, amber asks for attention, red flags a problem or a stalled case.

11Filtering the register

Find exactly the cases you need

  • 1Branch — pick a single owning branch.
  • 2Client Name / Customer / Account — type-ahead search boxes; suggestions narrow as you fill the others.
  • 3Upcoming Hearing — keep only cases with a hearing in a chosen window.
  • 4Product Category — SME by default.
  • 5Litigation Status — Active only by default; tick InActive to include closed cases.
  • 6Clear all — back to the default (Active + SME) view.
🔗

Filters are linked. Choosing a branch trims the Customer, Client-name and Account suggestion lists to just what's valid — so you can't search for a combination that doesn't exist.

12Upcoming hearing windows

Plan around the next hearing

The Upcoming Hearing dropdown buckets each case by when its next hearing date falls — invaluable for preparing the week or month ahead.

📅Today

Hearing is scheduled for the current date.

⏭️Next 5 Working Days

A hearing lands within the next five business days (bank holidays & weekends excluded).

🗓️This Month

Next hearing falls within the current calendar month.

➡️Next Month

Next hearing falls in the following calendar month.

⌛Later

A future hearing beyond next month.

⚠️Not Updated / No Date

Not Updated = the last hearing date has passed with no new date entered; No Date = none recorded.

🧮

"This Month" and "Next Month" are worked out from the real hearing date, so a case can appear in a month bucket even if it's also within the next-5-working-days window.

14Tips & good habits

Get more from the dashboard

🔄Start from Clear all

When a view looks off, hit Clear all to return to the known default (Active + SME) and rebuild your filter from there.

📆Check the Report Date

The data is a snapshot. Before you quote a number, glance at the Report Date in the top-right so you're citing the right day.

🔍Search beats scrolling

To find one client fast, type into Client Name or Customer rather than paging through thousands of rows.

🗂️Summary first, then drill

Use SUMMARY to spot where exposure sits, then jump to that suit's tab and filter to the same branch/status.

⏱️Watch the aging pills

Red duration pills in a case's history point to stages where the case stalled — useful when chasing law firms.

📤Filter, then export

The CSV always follows the on-screen filters, so set them precisely before downloading.
